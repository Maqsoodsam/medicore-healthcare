# Contribution Guidelines

## Branching

New development should be completed using a feature branch.

Example:

feature/patient-registration

## Commit Messages

Use clear and meaningful commit messages.

Good example:

Add patient registration validation

Poor example:

changes

## Java Coding Standards

- Use meaningful class, variable and method names.
- Follow standard Java naming conventions.
- Use PascalCase for class names.
- Use camelCase for variables and methods.
- Keep methods focused on a single responsibility.
- Avoid unnecessary duplicated code.
- Use consistent indentation and formatting.
- Add comments only where clarification is required.

## Before Committing Changes

Before committing changes:

1. Build the project.
2. Run all available tests.
3. Confirm that the application starts successfully.
4. Review the changed files.
5. Use a meaningful commit message.
